# Context Curation Roadmap

This roadmap describes how a future NWC Faculty Workbench could incorporate a Librarian-style context layer. It is a future direction, not a claim that NWC has solved secure deployment or institutional adoption.

Reference model: [The Librarian](https://codeministry.net/the-librarian/) and [JimJafar/the-librarian](https://github.com/JimJafar/the-librarian).

## Why This Matters

The workbench asks what faculty should save, review, and improve over time as AI-enabled teaching practices mature.

Context curation matters because AI-enabled teaching artifacts carry frames. If those frames travel across courses, faculty teams, or exercises, they should be visible, revisable, and faculty-governed.

## Current Layer: Markdown Workbench

Build now:

- assignment design worksheet;
- assessment rubric;
- flawed-output library template;
- faculty calibration protocol;
- source-kit template;
- after-action note.

This layer can live as plain markdown. It does not require an app.

## Future Layer 7: Institutional Memory

Purpose: preserve what usually disappears across faculty rotations.

Potential contents:

- lesson rationale;
- source kits;
- rubric revisions;
- flawed-output library entries;
- after-action notes;
- recurring student failure modes;
- faculty calibration notes.

Governance principle: faculty approve what becomes shared institutional context.

## Future Layer 8: Context Curation System

A Librarian-style system could add:

- markdown and git-backed vault;
- references that AI assistants can search without treating them as automatic memory;
- handoffs between faculty, courses, exercises, or AI-assisted sessions;
- proposal queues for suggested updates;
- flags for stale, misleading, or risky context;
- history, diffs, and rollback;
- dashboard review for faculty owners.

## NWC Translation Of Librarian Concepts

| Librarian concept | NWC workbench translation |
| --- | --- |
| Markdown vault | Faculty-governed source kits, rubrics, notes, and exercise artifacts. |
| References | Approved doctrine, cases, readings, and source packets. |
| Memories | Lessons learned, recurring failure modes, and course rationale. |
| Handoffs | Packaged exercise state, assumptions, COAs, constraints, and unresolved decisions. |
| Proposals | Suggested updates to source kits or rubrics requiring faculty approval. |
| Diffs and rollback | Version history for teaching artifacts and institutional context. |

## Operational Sandbox

Advanced exercises could use the context layer to support:

- multi-role AI planning workflows;
- student team handoffs;
- preservation of assumptions, constraints, COAs, and decision points;
- faculty review of how judgment evolved;
- proposals that route exercise discoveries back to the source kit.

## Cautions

- Do not put private course material in a public repo.
- Do not imply secure or classified deployment is solved.
- Do not let AI memory silently become institutional doctrine.
- Do not let a curator replace faculty approval.
- Do not treat prompt logs as proof of learning by themselves.
- Do not let a shared source kit narrow strategic imagination without review.

## Adoption Path

1. Use markdown templates manually.
2. Build faculty habit around source kits and after-action notes.
3. Create a small flawed-output library.
4. Run faculty calibration on common artifacts.
5. Pilot a governed context vault with public or approved internal materials.
6. Add proposal review before shared context changes.
7. Explore handoffs and operational sandbox workflows only after governance is working.
